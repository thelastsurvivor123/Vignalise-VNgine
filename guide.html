VIGNALISE VNGINE · STORY AUTHORING

Write your story in HTML.

Vignalise VNgine reads a small, regular-HTML structure and turns it into a branching visual novel. Write the source in the editor, follow the story in the live preview, and export or import the source whenever you like.

Open the editor → Read the first example
Example: a first story Expand to see a complete branching VN in HTML. +

Each scene is a regular HTML <section>, each dialogue line is a <p>, and choices are links.

<main data-vn-story data-title="A Small Beginning">
  <section id="start" data-scene>
    <p data-character="Mira" data-dialogue>
      The rain has finally stopped.
    </p>
    <p data-character="You" data-dialogue>
      <em>For now.</em>
    </p>
    <a data-choice href="#home">Walk home</a>
    <a data-choice href="#cafe">Find the open cafe</a>
  </section>

  <section id="home" data-scene>
    <p data-character="Mira" data-dialogue>
      The lights in your apartment are still on.
    </p>
  </section>

  <section id="cafe" data-scene>
    <p data-character="Barista" data-dialogue>
      We were just about to close. Come in.
    </p>
  </section>
</main>

Use the exact scene id in a choice’s href, preceded by #. For example, href="#cafe" goes to the scene with id="cafe".

Project explorer and image assets

The Explorer shows your browser-saved project together with repository files from the engine’s stories/ and assets/ folders. Repository entries are marked SOURCE and are read-only in the browser; change them in the engine’s VS Code folders and publish the site to update what everyone sees. Your own files remain separate in your browser.

You can delete the starter stories/example.html from your browser project; this only hides that example for you and does not change the shared engine files. Images provided by the engine are protected from deletion. Images you upload yourself remain part of your browser project and can be managed there.

To add shared content, place HTML stories in the repository’s stories/ folder and images in assets/. VS Code starts a watcher when this workspace opens; saving a story or image rebuilds the shared library, and an editor opened as file:// refreshes those files automatically. If automatic tasks are disabled, run powershell -NoProfile -ExecutionPolicy Bypass -File .\build-library-index.ps1 manually. When publishing the hosted site, include the updated library-index.json, library-data.js, and library-revision.js together with the stories and assets.

For a repository image shown in the Explorer, use its path in data-background:

<section id="garden" data-scene
  data-background="assets/garden.jpg">
  ...
</section>

Select an image uploaded to your browser project to reveal its unique asset ID. Use the ID in a scene’s data-background with the asset: prefix:

<section id="garden" data-scene
  data-background="asset:img-a1b2c3d4">
  <p data-character="Mira" data-dialogue>
    The garden is quiet.
  </p>
</section>

Replace img-a1b2c3d4 with the ID shown for your uploaded image. Project files and uploaded assets are stored in this browser on this device.

Story wrapper

Put the story inside one element marked data-vn-story. A data-title gives your project its name.

<main data-vn-story data-title="My story">
  ...
</main>

The story must contain at least one scene.

Scenes

Make each scene a direct child of the story wrapper. Give every scene a unique ID so choices can link to it.

<section id="station" data-scene>
  ...
</section>

Scene IDs should be simple and unique, such as station, chapter-2, or endingA.

Dialogue and narration

Each direct-child paragraph marked data-dialogue is one step. The reader clicks Continue to move to the next line.

<p data-character="Mira" data-dialogue>
  I thought you had left.
</p>
<p data-dialogue>
  The station clock ticks above you.
</p>

data-character is optional; leave it off for narration. Basic inline formatting such as <em>, <strong>, <br>, and <span> is supported inside dialogue.

Branching choices

Put choice links directly inside their scene. Choices appear after that scene’s dialogue has been read.

<a data-choice href="#market">
  Follow the music
</a>
<a data-choice href="#bridge">
  Take the quiet road
</a>

Every choice must point to a scene ID. Use #scene-id for a scene in the same file, or use a project-relative HTML path plus the scene ID to continue in another file. The path is relative to the HTML file containing the choice.

For example, if chapter-one.html is in stories/ and the ending file is stories/endings/reunion.html, link to the ending like this:

<!-- stories/chapter-one.html -->
<a data-choice href="endings/reunion.html#reunion">
  Choose the reunion ending
</a>

<!-- stories/endings/reunion.html -->
<section id="reunion" data-scene>
  <p data-dialogue>You find each other again.</p>
</section>

Keep linked stories inside the project and make sure the target file and scene ID exist. The editor preview follows links to stories available in the Explorer. For standalone playback of cross-file branches, export the project and drop or choose the complete ZIP on the home page; selecting just one HTML file cannot load its linked files.

Scene backgrounds

Add data-background to a scene to show an image behind its dialogue. Use an image URL the browser can access.

<section id="garden" data-scene
  data-background="https://example.com/garden.jpg">
  ...
</section>

Use https:// or http:// for a web image, or use an uploaded project image ID as described above. Project image data is saved in the virtual project and stays on this device.

Endings

A scene without choices ends its path after its dialogue. The reader can restart the story using the Restart button beneath the preview.

Save, export, and continue later

  • Your current source autosaves in this browser on this device.
  • Export project downloads a ZIP containing your project folders, HTML stories, uploaded images, and the repository stories/assets currently shown in Explorer. Choose the top-level project folder name when exporting.
  • Import project restores a project ZIP, including its folder name, active story, and image asset IDs. The ZIP is checked before import; you must confirm before it replaces the current browser project.
  • Drop or choose a project ZIP on the home page to play it. The standalone player supports links between HTML stories inside that ZIP; choosing one HTML file only supports links within that file.
  • Import replaces the project saved in this browser profile. Export a backup first if you want to keep that project.

The project ZIP can be played in Vignalise VNgine and is also an editable backup. Keep it to move your project to another browser or device.

A simple workflow

  1. Write or paste your HTML in the source editor.
  2. Check the live preview and follow the choices.
  3. Fix any messages shown below the editor.
  4. Export the project ZIP when you want a backup, want to share the project, or want to play branches across multiple HTML files.
